# Управление нодой: домены, обновление по запросу, своё ядро Xray, свежий rr — дизайн

Дата: 2026-11-26. Статус: согласован, реализован в ветке `feat/node-manage`.

## Зачем

Админ ставит ноды через `rr install node`, а дальше хочет менять их конфигурацию без
переустановки и ручной правки файлов: добавить или убрать selfsteal-домен, обновить nginx и
remnanode, поставить своё ядро Xray (форк по ссылке на бинарь). Тулкит на нодах должен
быть всегда актуальным без отдельной команды обновления. Установка не должна молча
переписывать A-запись домена: нода за балансером законно смотрит на чужой IP.

## Цели

1. **compose:** сертификаты в nginx монтируются двумя каталогами вместо пары файлов одного lineage:
   ```yaml
   - /etc/letsencrypt/live:/etc/nginx/ssl:ro
   - /etc/letsencrypt/archive:/etc/nginx/archive:ro
   ```
2. **Образ nginx** — `nginx:alpine`.
3. **`rr node update [nginx|node]`** — обновление образов nginx и remnanode до последней версии **по запросу админа**.
4. **`rr node domain add|del|list`** — правка `nginx.conf` на месте; при любом изменении проверяется наличие сертификата.
5. **`rr` при каждом запуске тянет актуальную версию** node-diagnostic.
6. **Своё ядро Xray по ссылке** — `rr node xray URL|off|status` и вопрос в `install node`; всё автоматически (скачать, проверить, смонтировать, пересоздать remnanode).
7. **DNS:** при несовпадении A-записи она меняется через API только с согласия.

## Не цели

- Автообновление по расписанию (таймер, cron, Watchtower) — явно отклонено.
- Правка профиля Xray в панели (`serverNames`): с ноды доступа к панели нет — только подсказка.
- Удаление сертификата при удалении домена.
- Обновление своего ядра: ссылка указывает на конкретную версию.
- `nginx.conf` нераспознаваемой структуры: нет ни одного блока selfsteal — отказ с объяснением.

## Анти-цели (провал, даже если «работает»)

- `rr` не запускается или висит, когда GitHub недоступен: диагностика ноды с поломанной сетью — основной сценарий тулкита.
- Изменение доменов применяет битый конфиг (nginx падает) или теряет ручные правки `nginx.conf` / `docker-compose.yml`.
- Обновление оставляет nginx на образе, на котором конфиг не проходит `nginx -t`.
- Молчаливая перезапись DNS.

## Ограничения

- bash 4+, стиль модулей (`msg_*`, `ui_head`, `ask`/`confirm`, `record_fix`), тексты на русском; `shellcheck --severity=warning` чистый (CI).
- `nginx.conf` и `nginx-main.conf` смонтированы в контейнер **файлами**: файл с новым inode (`mv`) контейнер не увидит. Писать на месте (`cat >`/`cp` поверх существующего) и делать `nginx -s reload`.
- certbot кладёт в `live/` относительные ссылки `../../archive/<lineage>/<f><N>.pem` — с маунтами из п.1 они разрешаются и внутри контейнера (`/etc/nginx/ssl/X/…` → `/etc/nginx/archive/X/…`). Абсолютные ссылки на `/etc/letsencrypt/archive/…` в контейнере битые — а именно такие сейчас создаёт `fix_letsencrypt_structure` (`modules/certs.sh`).
- Платформа как у `install node`: Debian 11+ / Ubuntu 22.04+, systemd, docker compose v2.

## Подходы

| Вопрос | Варианты | Выбор админа |
|---|---|---|
| Домены | A: список в `node.conf` + полная перегенерация `nginx.conf` (как `balancer`). B: правка существующего `nginx.conf` на месте — блоки `server` вставляются/убираются, ручные правки остаются | **B** |
| Обновление образов | A: свой systemd-таймер. B: Watchtower | **Ни то, ни другое — команда по запросу админа** |
| Актуальность тулкита | A: самообновление внутри `node-diagnostic.sh` по условиям. B: в обёртке `rr` | **При каждом запуске `rr` безусловно тянется актуальная версия** — делается в обёртке `rr` |

## Как устроено

### 1–2. compose и сертификаты

- `node_render_compose`: в volumes nginx — две строки каталогов вместо двух файлов; аргумент lineage больше не нужен. `NGINX_IMAGE="nginx:alpine"`. Пути в `nginx.conf` не меняются: `/etc/nginx/ssl/<lineage>/fullchain.pem`.
- `fix_letsencrypt_structure` создаёт относительные ссылки `../../archive/<lineage>/<f><N>.pem`, как certbot. Свой сертификат (`manual`) — обычные файлы в `live/`, работают как есть.
- **Миграция существующего compose на месте** (`node_compose_migrate`): удалить строки `- /etc/letsencrypt/live/…:/etc/nginx/ssl/…:ro`, добавить два каталога, если их нет; `image: nginx:<любой тег>` у `remnawave-nginx` → `nginx:alpine`. Остальное в файле не трогается; бэкап `docker-compose.yml.bak-<время>`. Вызывается из `node update`, `node domain add|del`, `node xray`. Если файл изменился — `remnawave-nginx` пересоздаётся (`docker compose up -d remnawave-nginx`), а не перезагружается.

### 3. `rr node update [nginx|node]` (без аргумента — оба)

1. Нода установлена (`$REMNANODE_DIR/docker-compose.yml` с сервисами `remnawave-nginx`/`remnanode`), иначе отказ.
2. Миграция compose (выше).
3. Запомнить image ID сервисов, `docker compose pull <сервисы>`.
4. nginx: если образ сменился — `docker run --rm` новым образом с теми же маунтами (`nginx-main.conf`, `nginx.conf`, `live`, `archive`, web root) и `nginx -t`. Провал → nginx не пересоздаётся, вывод ошибки, итоговый rc ≠ 0; remnanode при этом обновляется.
5. remnanode: в TTY — предупреждение «клиенты ноды отвалятся на несколько секунд» и confirm. Без TTY — без вопроса (команда явная).
6. `docker compose up -d <сервисы>` — compose сам пересоздаёт только изменившиеся.
7. Вывод «было → стало» (версия nginx, версия ядра в remnanode), `docker image prune -f` (только dangling), `record_fix`.
8. Своё ядро подключено → предупреждение: ядро не обновлялось (версия X); при несовместимости — `rr node xray off` или новая ссылка.

### 4. `rr node domain add|del|list`

**Распознавание.** Сайт selfsteal — блок `server { … }` верхнего уровня, в котором есть `listen unix:/dev/shm/nginx.sock ssl proxy_protocol` без `default_server`. Разбор по глубине фигурных скобок. Блоки `default_server` (reject) и `listen 80` не трогаются никогда.

**list:** по каждому сайту — имена из `server_name`, lineage из `ssl_certificate`, есть ли файлы на хосте, дней до истечения.

**add `<домен>`:**
1. `is_domain`, домена ещё нет ни в одном `server_name`.
2. DNS — `check_domain "$домен" false` (п.7).
3. Сертификат — `resolve_certificate_domain`. Нет: в TTY — предложить выпуск (`certs_for_domain`); без TTY — отказ с подсказкой `rr certs issue <домен>`.
4. Миграция compose (каталоги смонтированы, иначе nginx не увидит чужой lineage).
5. Новый блок — **копия первого сайта** (сохраняет ручные правки: заголовки, `location`) с заменой `server_name` и путей `ssl_certificate` / `ssl_certificate_key` / `ssl_trusted_certificate` на lineage нового домена. Вставляется сразу после последнего сайта.
6. **Проверка перед записью:** каждый `ssl_certificate*` итогового конфига указывает на существующий непустой файл на хосте (`/etc/nginx/ssl/` → `/etc/letsencrypt/live/`); затем `nginx -t` во временном контейнере (образ `remnawave-nginx`, итоговый файл и те же маунты).
7. Запись на месте (бэкап `nginx.conf.bak-<время>`) → `docker exec remnawave-nginx nginx -s reload` (или пересоздание, если менялся compose). Провал reload → вернуть бэкап на месте и reload. Контейнер не запущен → только запись и предупреждение.
8. Подсказка: добавить домен в `serverNames` профиля Reality в панели.

**del `<домен>`:**
- Имя в `server_name` с несколькими именами → убрать только имя; единственное имя → удалить блок целиком.
- Последний домен ноды — отказ.
- Та же проверка (сертификаты оставшихся сайтов + `nginx -t`), запись на месте, reload.
- Сертификат остаётся. Подсказка: убрать домен из `serverNames`.

### 5. `rr` — актуальная версия при каждом запуске

Обёртка `/usr/local/bin/rr` (пишет `install.sh`, в неё зашиты `REPO`, `REF`, `DEST`):
1. Не root → `exec sudo` себя же (как сейчас).
2. Под root: `$DEST/.git` есть → `git fetch --depth 1 origin $REF && git reset --hard FETCH_HEAD` под `timeout` (~15 с), с тем же исправлением `origin`, что в `install.sh`. Нет git или `.git` → tarball, как в `install.sh`.
3. Ошибка → предупреждение «не обновился (нет доступа к GitHub?) — запускаю локальную vX», запуск локальной копии.
4. `ND_NO_PULL=1` — пропустить подтягивание.
5. Обёртка не исполняет файлы, которые сама перезаписывает: логика подтягивания живёт внутри обёртки (или `install.sh` копируется во временный файл и запускается оттуда в режиме «только обновить»). Перезапись запущенного bash-скрипта на месте ломает его выполнение.

Уже установленные ноды: у них старая обёртка. Нужно один раз выполнить установочную команду (`curl … install.sh | sudo bash`) — она обновит репозиторий и перепишет обёртку. Это пишется в README и CHANGELOG.

### 6. Своё ядро Xray

**`rr node xray <URL>`:**
1. Скачать в `/opt/xray-core/xray.new` (`download_file`; для `github.com` — с перебором `GH_PREFIXES`).
2. Формат: ELF → как есть; zip (`PK`) → извлечь `xray` (официальные релизы XTLS — zip).
3. Проверки: ELF; архитектура из заголовка совпадает с `uname -m` (x86_64 / aarch64); `docker run --rm --entrypoint /usr/local/bin/xray -v …/xray.new:/usr/local/bin/xray:ro <образ remnanode> version` печатает `Xray …`. Образ remnanode должен быть уже скачан (`docker compose pull remnanode` при необходимости).
4. `mv` на место `/opt/xray-core/xray`, `chmod 755`. Новый inode — remnanode всё равно пересоздаётся.
5. В compose под `remnanode.volumes` — строка `- /opt/xray-core/xray:/usr/local/bin/xray:ro`, если её нет (на месте, бэкап).
6. `docker compose up -d --force-recreate remnanode`, показать версию ядра в контейнере.
7. URL и версия → `/opt/xray-core/SOURCE` (для `status`).

Remnanode с новым ядром не поднялся (контейнер не в состоянии `running` через 3 с) → откат: было своё ядро — возвращается прежний бинарь (`xray.prev`), было встроенное — том убирается; remnanode пересоздаётся.

**`rr node xray off`:** убрать строку из compose, пересоздать remnanode. Файл ядра остаётся на диске.
**`rr node xray status`:** встроенное или своё, версия, URL.
**`install node`:** вопрос «Своё ядро Xray — ссылка на бинарь [Enter — встроенное]»; ядро ставится после записи compose, до `docker compose up -d`. Не скачалось или не прошло проверку → предупреждение и установка со встроенным.

### 7. DNS: смена A-записи только с согласия

`check_domain`: при несовпадении (чужой IP, прокси Cloudflare, записи нет) показывается «домен → X, сервер → Y» и выбор:
- **[1]** записать `домен → IP сервера` через API: сохранённый ключ → его провайдер, иначе выбор провайдера (Cloudflare / Gcore / Bunny) или «создам сам»;
- **[2]** оставить как есть и продолжить (Enter);
- **[0]** отмена.

`ensure_dns_record` больше не пишет запись сразу по сохранённому ключу — только после [1]. Одинаково для всех трёх провайдеров.

- Главное меню: новый пункт **[14] Управление нодой** — домены (список / добавить / удалить), обновить nginx / remnanode / оба, ядро Xray (своё по ссылке / вернуть встроенное / статус).

### Тесты (smoke, без сети)

- Рендер compose: две строки каталогов, `nginx:alpine`, нет файловых маунтов сертификата; с ядром — строка xray у remnanode; `docker compose config`, где есть docker.
- Миграция старого compose (фикстура с файловыми маунтами и `nginx:1.30.6-alpine`): ручная строка в файле сохраняется.
- `domain add/del` на фикстуре `nginx.conf` с ручным `location`: копия блока его сохраняет; удаление имени из многоименного `server_name`; отказ на последний домен; `default_server` и `:80` не тронуты; отказ на домен без сертификата (без TTY).
- `nginx -t` (`nginx:alpine`) многодоменного конфига с самоподписанными сертификатами в структуре `live/` + `archive/` с относительными ссылками — подтверждает, что маунты каталогов работают.
- `fix_letsencrypt_structure` создаёт относительные ссылки.
- `check_domain` с сохранённым ключом и несовпадением: без ответа [1] API не вызывается (заглушка `curl`).
- Обёртка `rr`: недоступный origin → предупреждение и запуск локальной копии (rc 0); `ND_NO_PULL=1` не трогает git.
- xray: проверка ELF/архитектуры и извлечение из zip на фикстурах.

## Решения, принятые без админа (на проверку)

1. `node update` для remnanode спрашивает подтверждение в TTY (обрыв клиентов).
2. `node update` заодно мигрирует старый compose (маунты, тег nginx) — иначе обновление оставило бы старый закреплённый `nginx:1.30.6-alpine`.
3. Новый домен — копия первого сайта, все домены ноды отдают один и тот же сайт из `/var/www/html`.
4. Нет сертификата: в TTY — предложить выпуск, без TTY — отказ.
5. DNS: по умолчанию «оставить как есть»; для всех трёх провайдеров, не только Cloudflare.
6. `rr`: при ошибке подтягивания — локальная версия с предупреждением; `ND_NO_PULL=1` отключает.
7. `xray off` оставляет файл ядра на диске.
8. Пункт меню [14].
