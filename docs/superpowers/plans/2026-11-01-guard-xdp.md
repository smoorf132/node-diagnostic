# `rr guard`: NOTRACK + гео-фильтр RU + SYN cookies на XDP — план внедрения

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Опциональный модуль `rr guard`, который в двух вариантах снимает с портов 443/80 conntrack (NOTRACK), отвечает на SYN-флуд cookie-ответами прямо из XDP и (вариант 1) ещё и дропает на XDP всё, что пришло на эти порты не из России.

**Architecture:** Две BPF-программы с общими картами. XDP (`nd-guard-xdp.bpf.c`) — гео-фильтр по LPM-картам и ответ SYN-ACK с cookie через `XDP_TX`. tc ingress (`nd-guard-tc.bpf.c`) — проверка cookie в ACK и создание соединения в ядре через kfunc `bpf_sk_assign_tcp_reqsk` (ядро ≥ 6.9); conntrack не нужен ни на одном шаге. NOTRACK — своя nft-таблица `inet nd_guard` с raw-приоритетом. Оркестратор `modules/guard.sh` по образцу `shape.sh`: on/off/status/reattach, systemd на boot, таймер обновления гео-списка, dead-man-откат после включения.

**Tech Stack:** bash + `lib/common.sh`; clang `-target bpf` с UAPI-заголовками и libbpf (`bpf_helpers.h`), без vmlinux.h — как у `nd-shaper.bpf.c`; bpftool; iproute2 (`ip`, `tc`); nftables; python3 (только stdlib).

**Spec:** отдельного spec нет — пользователь попросил сразу план. Требования и все принятые решения — в разделе «Требования и решения» ниже; исполнитель читает его как spec.

## Требования и решения

**От пользователя:**
- Вариант 1: conntrack NOTRACK на 443/80 + всё, что не Россия, — DROP + SYN cookies на XDP, остальное — дальше в стек.
- Вариант 2: то же самое, но без дропа «не Россия».
- Защита превентивная и опциональная: по умолчанию выключена, включается командой или из меню.

По уровням это L3/L4 (IP/TCP), а не L7: содержимое TLS/HTTP не разбирается.

**Решения (приняты при планировании, на ревью пользователю):**

- **D1. Cookies без conntrack.** Классическая связка «XDP + nft `synproxy`» держит conntrack-запись на каждое установленное соединение и делает seqadj на каждом пакете — это противоречит NOTRACK. Поэтому: SYN → XDP сам отвечает SYN-ACK с cookie (`XDP_TX`); ACK → tc-BPF проверяет cookie и вызывает `bpf_sk_assign_tcp_reqsk` (upstream «bpf: tcp: Support arbitrary SYN Cookie», ядро 6.9). Ядро принимает такой ACK в `cookie_v4_check` через `cookie_bpf_check` и берёт `rcv_wscale` из наших атрибутов. Наличие kfunc определяется по BTF ядра (`/sys/kernel/btf/vmlinux`), а не по номеру версии.
- **D2. Ядро без kfunc.** XDP-cookies выключаются; остаются NOTRACK, гео (вариант 1) и штатные syncookies ядра. `guard on` и `guard status` прямо пишут об этом и советуют `rr bbr3 --install` (XanMod ≥ 6.9). XDP цепляется только тогда, когда у него есть работа: гео включено или cookies доступны. Вариант 2 на старом ядре = только NOTRACK. Generic XDP без дела не вешаем: он линеаризует GRO-пакеты и съедает пропускную способность.
- **D3. Режим cookies по умолчанию — `auto`.** XDP отвечает cookie, только когда поток SYN (уже после гео-фильтра) превышает порог — по умолчанию 10000 SYN/с, — и ещё 60 с после этого. Режимы `always` и `off` включаются флагом. Причина: ошибка в cookie-пути бьёт только во время атаки. Опции не теряются: MSS, wscale и SACK кодируются в cookie, TCP timestamps берутся из ACK, поэтому клиенты без timestamps (Windows) сохраняют window scaling.
- **D4. Формат cookie** (свой, по образцу upstream selftest `test_tcp_custom_syncookie.c`): `cookie = hash24 << 8 | mss_idx(3 бита) << 5 | sack << 4 | wscale(4 бита, 15 = клиент не прислал WS)`. `hash24` — старшие 24 бита SipHash-2-4 с ключом 128 бит по {адреса, порты, ISN клиента, слот времени, байт опций}; байт опций входит в хэш, поэтому подделать его нельзя. Слот = `ktime_ns >> 36` (~68,7 с); принимаются текущий и предыдущий слоты. Ключ — 16 байт из `/dev/urandom` в `GUARD_DIR/key` (права 600).
- **D5. Гео-список RU** = объединение двух источников: RIPEstat country-resource-list (страна регистрации в RIR) и db-ip country lite (геолокация, лицензия CC BY 4.0, нужна атрибуция в README). Объединяем, чтобы реже резать своих. Проверка здравости: v4 ≥ 25 000 000 адресов и ≥ 3000 префиксов, v6 ≥ 300 префиксов; иначе список не принимается. Если годного списка нет ни из сети, ни в кеше, `guard on --geo ru` отказывает: пустой allowlist дропнул бы всех. Обновление — раз в неделю (systemd timer); в карту сначала добавляются новые префиксы, потом удаляются старые.
- **D6. Порты** по умолчанию 443 и 80, TCP и UDP (UDP 443 — QUIC/Hysteria2), меняются флагом `--ports`. Каждый порт обязан быть ниже начала `net.ipv4.ip_local_port_range` (`optimize` ставит 10000), иначе NOTRACK и гео задели бы ответы на исходящие соединения ноды.
- **D7. Гео на 80 и ACME HTTP-01.** Валидаторы Let's Encrypt ходят из-за рубежа. certbot pre/post-хуки (`/etc/letsencrypt/renewal-hooks/{pre,post}/node-diagnostic-guard.sh`) на время продления снимают гео-флаг с порта 80 и возвращают его после.
- **D8. Allowlist** (`guard allow IP|CIDR`) обходит и гео, и cookies. Нужен для CDN-фронтинга (xhttp через Cloudflare: без allowlist вариант 1 отрежет весь такой трафик), каскадов и админа за рубежом.
- **D9. Fail-open.** Любая ошибка (компиляция, attach, kfunc вернул ошибку, невалидный cookie в ACK) → пакет идёт в ядро как без защиты. DROP есть только в одном месте — гео-решение. Невалидный cookie-ACK не дропается: ядро само ответит RST или примет собственный syncookie.
- **D10. Применение.** Как у `shape`, защита применяется сразу, а не генерирует файлы. Но после `guard on` взводится dead-man: `systemd-run --on-active=300` вызывает `guard off`. Снимается командой `guard confirm` или ответом «y» на интерактивный вопрос. SSH-порт guard не трогает.
- **D11. Сосуществование с шейпером на clsact.** Ingress-фильтр guard ставится с `pref 10` и всегда возвращает `TC_ACT_UNSPEC`: `TC_ACT_OK` остановил бы цепочку, и UL-фильтр шейпера не выполнился бы. Шейпер получает `pref 49200`. Никто больше не делает `tc qdisc del … clsact`: qdisc удаляет тот, кто уходит последним.
- **D12. Режим XDP.** Сначала native (`xdpdrv`). Если virtio не даёт (`GRO_HW`), выключаем `rx-gro-hw` и пробуем снова, запомнив, что вернуть на `off`. Иначе `xdpgeneric` с предупреждением. Если на интерфейсе уже висит чужая XDP-программа — отказ.
- **D13. Docker bridge** с опубликованным 80/443 (DNAT) несовместим с NOTRACK → `guard on` отказывает. Штатная нода (`network_mode: host`) — ок.
- **D14. Состояние** — в `/var/lib/node-diagnostic/guard/` (переживает reboot), а не в `ND_STATE_DIR` (это `/run`, tmpfs).

**Алгоритм XDP** (то, чего не выведешь из сигнатур):
1. Eth: VLAN и прочие ethertype → PASS. IPv4: `ihl != 5` или фрагмент → PASS. IPv6: `nexthdr` не TCP/UDP → PASS.
2. `flags = guard_ports_map[dport]`; бита нужного L4-протокола нет → PASS, статистика не пишется.
3. Попадание в `allow4_map`/`allow6_map` → `ST_ALLOW`, PASS.
4. `geo_on && (flags & GUARD_P_GEO)` и промах по `geo*_map` → `ST_GEO_DROP`, DROP.
5. TCP с SYN без ACK: `ST_SYN`; окно 1 с — если `now - win_start > 1e9`, обнулить окно; `n = __sync_fetch_and_add(&win_syn, 1) + 1`. Если AUTO и `n > syn_threshold`, то `attack_until = now + hold_sec*1e9`. Cookie-ответ, если ALWAYS или (AUTO и `now < attack_until`) → собрать SYN-ACK, `ST_COOKIE_SENT`, `XDP_TX`.
6. Иначе `ST_PASS`, PASS.

**SYN-ACK:**
- Заголовки: MAC/IP/порты меняются местами; `seq = cookie`, `ack = isn + 1`, флаги `SYN|ACK`, `window = 65535`.
- Опции: `MSS(cfg.mss4|mss6)`; если клиент прислал TS — `SACKOK,TS` (при SACK) или `NOP,NOP,TS`; если TS нет, но есть SACK — `NOP,NOP,SACKOK`; если клиент прислал WS — `NOP,WS(cfg.rcv_wscale)`.
- TS: `tsval = (u32)(now_ns / 1000000)`, `tsecr` = tsval клиента. MSS клиента отсутствует → 536 (v4) / 1220 (v6). WS клиента > 14 → 14.
- IPv4: TTL 64, DF, id 0. IPv6: hop limit 64.
- Длина пакета — через `bpf_xdp_adjust_tail`, чексуммы IP и TCP — заново через `bpf_csum_diff`.

**Алгоритм tc** (всегда возвращает `TC_ACT_UNSPEC` — см. D11):
1. Cookie-режим `OFF` → выход. `AUTO` и `now > attack_until + 2·2^36` нс → выход (выданные cookie уже протухли).
2. TCP на порт с `GUARD_P_TCP`, есть ACK, нет SYN и RST; иначе выход.
3. `bpf_skc_lookup_tcp(tuple, BPF_F_CURRENT_NETNS)`: NULL → выход; `state != BPF_TCP_LISTEN` → release, выход.
4. `nd_cookie_check(cookie = ack_seq - 1, isn = seq - 1, ND_COOKIE_SLOT(now))` не прошёл → `ST_COOKIE_BAD`, release, выход (ядро решит само — D9).
5. TS-опция в ACK есть → `tstamp_ok = 1`, `rcv_tsval`/`rcv_tsecr` из ACK.
6. `attrs`: `mss = opts.mss`, `wscale_ok`, `snd_wscale`, `rcv_wscale = wscale_ok ? cfg.rcv_wscale : 0`, `sack_ok`, `ecn_ok = 0`, `usec_ts_ok = 0`, `reserved` нулевые.
7. `bpf_sk_assign_tcp_reqsk(skb, (struct sock *)bpf_skc_to_tcp_sock(skc), &attrs, sizeof(attrs))`: `< 0` → `ST_ASSIGN_ERR`, иначе `ST_COOKIE_OK`; release.
